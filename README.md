共 300 題。跟每週頁面不一樣的地方：

- **題目不寫在 HTML 裡**，六份共用 `assets/data-exam.js`，由 `python tools/extract-exams.py` 直接從 `../考古題/*.pdf`
  產生（需要 PyMuPDF）。腳本會用兩種方法各抽一次答案（文字順序、字的座標），不一致就中止，不會默默寫錯答案。
  iPAS 公告新一次試題時：PDF 放進 `考古題`、在腳本的 `SITTINGS` 加一筆、重跑腳本，再照現有頁面複製一份 `exam-*.html`。
- `initQuiz` 多了三個設定：`exam: true`（「帶去 AI 問」改成把錯題連四個選項、官方答案整段帶過去，請 AI 逐題講解）、
  `minutes: 75`（計時器，可暫停；時間到只提醒、不強制交卷。**目前沒啟用**，見下方中斷接續）、
  `passLine: 70`（結果顯示「分」並提示離單科及格線多遠）。題目沒有 `e`（解析）時只顯示答案。
- `day` 用 `'exam114-4-1'` 這種字串；成績表的週次欄是 `STEP3`、天數欄是 `114年第四次 科目一`。
  後端 `queryStatus_()` 靠這兩欄換算回 `exam114-4-1`，**所以後端要部署新版本**，考古題的完成狀態查詢、
  換裝置還原、錯題複習才查得到（沒部署的話送出成績一樣會寫進試算表，只是查不回來）。
- 頁面加了 `<body class="exam">`，條列題（1. 2. 3.／（甲）（乙））的換行只在考古題頁顯示，不影響各週頁面。

**中斷接續**（只有考古題頁，`exam: true` 才啟用）：50 題、75 分鐘不一定能一次做完，所以作答進度會暫存。

- 存什麼：選了哪些選項、最後作答的是第幾題（`at`，「📍 回到第 N 題」用）。
  計時器目前**關閉**（2026-09-23 同仁不需要）：頁面上沒有 `timer-btn`、`initQuiz` 也沒給 `minutes`，
  `initTimer()` 就不啟用。要恢復的話兩樣加回去即可，已用秒數會自動跟著進度一起暫存。
- 「💾 暫存」和「📍 回到第 N 題」都在右下角的浮動框（`#float-pill`），跟著畫面走；接續進度後才會出現「回到第 N 題」，
  按了捲到上次最後作答的下一題並閃一下，之後邊做邊更新。
- 存在哪：每點一個選項就存進這台裝置的 localStorage；有填姓名時，**停手 15 秒、按「💾 暫存」、
  或切走分頁／關閉頁面**都會送到後端，寫進試算表的 **「考古題作答進度」** 工作表。
  這張表**一人一份考古題只有一列**，之後的暫存都覆蓋同一列（後端 `SPECS.draft.sameRecord`），
  交卷後狀態改成「已交卷」。召集人打開這張表就看得到誰做到哪（計時器關閉期間「已用時間」欄都是 0）。
- 怎麼接：打開同一份考古題頁、填同一個姓名（暱稱也行，會經 `NAME_MAP` 合併），前端向後端查
  `drafts`，跟本機的進度比「最後更新時間」，用比較新的那份。換裝置的人是打開頁面之後才填姓名，
  所以姓名欄 `change` 時會再查一次。
- 考古題總覽頁的卡片會顯示「作答中 · 已答 N / 50 題」。

題目卡片上都會標「官方原題」或「自編練習題」。

## 部署到 GitHub Pages

```bash
git init
git add .
git commit -m "W1 每日學習網站"
git branch -M main
git remote add origin https://github.com/<你的帳號>/<repo 名稱>.git
git push -u origin main
```

推上去之後，到 repo 的 **Settings → Pages**：

- **Source** 選 `Deploy from a branch`
- **Branch** 選 `main`、資料夾選 `/ (root)`
- 按 Save，等一兩分鐘

## 成績記錄

見 [SETUP.md](SETUP.md)。簡單說：開一份新的 Google 試算表 →
貼上 `apps-script-backend.gs` → 部署為網頁應用程式 →
把網址填進 `assets/config.js`。

這是讀書會網站**自己的**後端，跟鑑別測驗那份 Apps Script 是分開的兩套，
之後要加的功能都往這一份加。成績寫進「每日測驗結果」工作表。

要擴充時只需要改 `apps-script-backend.gs` 最上面的 `SPECS`：
每種要記錄的資料就是一個項目（寫到哪個工作表、欄位、怎麼轉成一列），
新增類型不用改 `doPost`。檔案最下方附了「週五打卡」的現成範例。

> 改完程式碼一定要「部署 → 管理部署作業 → 版本選新版本 → 部署」，
> 只按 Ctrl+S 儲存不會生效。

## 下一週要加內容時（W6 已完成，STEP 2 結束，下一站是 STEP 3 考古題）

W1～W6 都已經開通、可以隨時回頭補進度，所以**不要**覆蓋既有的 `wN-index.html` 或
`dayN.html`——新週次一律用新檔名（W7 就用 `w7-index.html`、`day31.html`…`day35.html`、`w7-test.html`）。
`tools/extract-questions.js` 最下面也要照樣加一組 `buildWeek([...], 'W7_QUESTIONS', 'data-w7.js')`。

1. 複製上一週的 `dayN.html` 改成新的一天（複製 `w2-index.html`、`w2-test.html` 當範本）
2. 改最下面 `Study.initQuiz({...})` 裡的 `day`、`dayTitle`、`questions`，**還有這兩個容易漏掉的**：
   - `week: 'W3'` —— 沒給的話成績表週次欄會錯標成 W1
   - `subject: '科目二「生成式AI應用與規劃」'`（或對應科目）—— 沒給的話「帶去 AI 繼續問」的提示文字會錯講成科目一
3. 新週次自己的 `wN-index.html` 裡加齊 `daycard`，`data-day` 要跟 `initQuiz` 的 `day` 一致
4. 每一頁的 `.daynav` 加上新的連結，記得把「總覽」指到自己這週的 `wN-index.html`（不是課程首頁 `index.html`）
5. `index.html`（課程首頁）加一張新的週次卡片，把上一週卡片的「本週」badge 改回一般樣式
6. 舊週次 `wN-index.html` 的 mast-meta 可以補一個「下一週 →」的 `<a class="tag">` 連結

`day` 是進度記錄的唯一鍵，跨週請不要重複（W1 用 1～5、W2 用 6～10、W3 用 11～15，以此類推；
目前用到 W6 的 26～30，下一週從 31 開始）。

**總測驗這種不是「第幾天」的頁面**，`day` 可以直接給字串（例如 `'w3test'`），
另外三個設定要一起給，否則會出錯或寫進奇怪的資料：

| 設定 | 作用 | 不給會怎樣 |
| --- | --- | --- |
| `dayLabel` | 試算表「天數」欄直接寫這個字串 | 會寫成 `Day w3test` |
| `pageFile` | AI 提問裡附的網址檔名 | 會湊成 `dayw3test.html`（404） |
| `scopeWord` | AI 提問裡的稱呼，例如 `'這一週'` | 會講成「今天」 |

後端 `SPECS.daily.row` 是 `d.dayLabel ? d.dayLabel : (d.day ? 'Day ' + d.day : '')`，
所以**改了這三個設定不用動後端**；`week`／`subject` 也是純前端設定，同樣不用動後端或重新部署。

## 已知限制

- 每日進度存在瀏覽器 localStorage，換裝置就要重做。成績以試算表為準。
- 網站沒有身分驗證，姓名是同仁自行輸入。
- 需要網路連線才能回傳成績；離線時仍可作答與看解析。
